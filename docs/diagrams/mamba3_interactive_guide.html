01 / Representation flow

Two residual branches in every block.

The embedding creates a [B,T,1024] representation. Each of the 28 blocks first mixes information across sequence positions with complex SSD, then applies a position-wise SwiGLU feed-forward network. A residual addition follows each branch.

h = RMSNorm(x) q = in_proj(h) # 1024 → 5136 channels u = SSD(q.x, A, q.B, q.C, q.dt) x = x + out_proj(MIMO(u)) x = x + SwiGLU(RMSNorm(x)) # FFN width 2048 logits = tied_head(final_norm(x)) # after all 28 blocks

The input projection emits 16 × (64 + 4×64 + 1) = 5136 channels per token. A single matrix multiplication produces the SSD input, real/imaginary B and C components, and the raw step-size values. The learned complex A has one scalar per head and is initialized to −1.

Projection sliceRoleReshaped tensor
0:1024Real input x[B,T,16,64]
1024:3072B real + imaginary[B,T,16,64] complex64
3072:5120C real + imaginary[B,T,16,64] complex64
5120:5136Raw dt[B,T,16], softplus inside SSD

MIMO flattens the 16 heads and 64 channels into a 1024-vector, applies a dense 1024×1024 matrix and restores the shape. It mixes both head and channel coordinates. Identity initialization initially passes the scan output through unchanged; it does not guarantee future stability. The model-wide initializer preserves that identity.

Input embedding and output head share weights at vocabulary size 50,257. The standard configuration has approximately 434M parameters. It contains no causal convolution. The model returns a full [B,T,50257] logits tensor; it has no hidden-state-only loss interface or incremental state-cache API.

02 / State-space duality

Decay controls memory. Rotation controls phase.

For each head, let A = α + iω and Δ = softplus(dt). The transition exp(ΔA) scales the state by exp(Δα) and rotates it by Δω. Negative α forgets older inputs; the imaginary component permits oscillatory dynamics. A is learned directly, so a negative real part is an initialization choice, not an enforced parameter constraint.

aₜ = exp(softplus(dtₜ) × A) sₜ = aₜ sₜ₋₁ + Bₜ ⊗ xₜ yₜ = Re(Σₙ Cₜ,ₙ sₜ,ₙ) state shape: [B,H,N,D] = [B,16,64,64]

The readout is a complex bilinear contraction; the code does not conjugate C. The sequential oracle starts from a zero state. The production chunkwise function reorganizes the same recurrence and returns the real part.

Within chunks, then across chunks.

With chunk length C=64, an inclusive prefix sum of A_log = softplus(dt)×A gives each source-to-destination decay. Inside a chunk, L[l,s] = exp(prefix[l] − prefix[s]) for s≤l, and zero otherwise. The lower triangle includes the diagonal. Einsum combines input x, B, C and L to produce Y_diag and chunk-end states.

The implementation then constructs a strictly lower-triangular decay matrix over chunk pairs, propagates completed chunk states with an einsum, and adds Y_off. It does not run a serial T/C loop: the explicit chunk-pair matrix has a (T/C)² storage term. Therefore a blanket “linear training memory at every context length” claim would be misleading. The mathematical recurrence admits fixed-size streaming state, but the public model does not expose that incremental interface.

Y = Re(Y_diag + Y_off) 64 complex64 entries × 8 bytes = 128 float32 entries × 4 bytes Both occupy 512 bytes per state/channel slice.

Complex packing halves the number of named state entries, not their byte count at these dtypes. Perplexity parity with another trained model requires evaluation; the local numerical test compares the chunkwise algorithm with its sequential oracle.

03 / Corpus to tensors

The file suffix is not a storage contract.

The canonical shared recipe targets 8B tokens: FineWeb-Edu 40%, DCLM 15%, Stack Python 15%, Stack Jupyter 5%, OpenMath 10%, arXiv 10% and Cosmopedia 5%. The older five-source mix in configuration comments is not the active preparation recipe.

The local preparation shim delegates download, cleaning, deduplication, tokenization and packing to workspace shared_data. It writes a GPT-2 tokenizer override: V=50,257, EOS=50,256, PAD=50,256. Packed document boundaries require EOS separators. The producer emits raw uint32 shards, conventionally 50M tokens each—about 200 MB of raw payload.

Current integration gap: PretrainDataset opens shard_*.bin with torch.load(weights_only=True, mmap=True). That API expects serialized PyTorch tensors, not raw uint32 bytes. No conversion bridge is implemented by this preparation shim. The diagram marks this handoff as a mismatch; successful preparation alone does not establish trainability.

For compatible serialized tensor shards, the loader builds cumulative offsets and locates a global token index with binary search. It gathers a 2049-token window across shard boundaries using torch.cat, converts to long, and returns the first/last 2048 tokens as input and target. The stride is 2048, so neighboring windows share the boundary token.

window: [A, B, C, EOS, D] input: [A, B, C, EOS] target: [B, C, EOS, D]

The trainer builds DataLoader with batch size 16, num_workers=0 and drop_last=True. Shuffle and pin_memory use their False defaults. Device transfers request non_blocking=True, but that alone does not prove overlapped pinned-memory transfer. Memory mapping avoids an eager full-file load; resident pages, torch.cat, dtype conversion and batch collation still consume memory.

04 / Learning and recovery

Micro-steps and optimizer updates are different clocks.

Pretrainer builds the model, optional torch.compile wrapper, AdamW and warmup/cosine schedulers. Eligible CUDA operations use BF16 when supported; CPU smoke tests disable autocast. The raw model remains available for checkpointing. AdamW uses fused=False and separates decay by tensor rank: tensors with rank at least two decay, one-dimensional parameters do not.

Forward → full-logit CE → loss / accumulation → finite-loss check → backward → every 2 micro-steps: clip 1.0 → AdamW → scheduler → zero gradients
SettingActual interpretation

max_steps = 256,000Successful micro-steps; nominally 128,000 updates and 8,388,608,000 token positions, excluding recovery replays.
Learning rateWarmup from 1% of 3e-4 (3e-6) to 3e-4 over 2000 optimizer updates; cosine target 1.5e-5.
Schedule horizonCosine T_max is max_steps − warmup_steps. Because it advances on optimizer updates, the default run does not reach the configured cosine endpoint.
Logging / savingEvery 50 / 4000 counted micro-steps; checks precede the global_step increment. A final checkpoint follows the loop.

If loss is nonfinite, the guard clears gradients and skips backward. After five consecutive bad losses it restores the latest complete checkpoint, or raises if none exists. It is a finite-loss check, not a general detector of finite loss spikes or nonfinite gradients.

CheckpointManager writes model safetensors, optimizer state and JSON metadata directly. Latest-step discovery requires all three paths to exist; that is not an atomic transaction or a file-integrity check. Metadata carries scheduler state, optimizer-step count and configuration. RNG state and sampler/data position are not persisted, so bit-exact resume is not established. The training loop has no held-out validation or sample-generation hook.

05 / Resource budgets

What is implemented—and what is only a proposal.

MechanismBenefit and boundary
Chunkwise complex SSDExposes within-chunk contractions in parallel. This implementation also materializes cross-chunk pairwise decay; its scaling must be measured.
Gradient checkpointingRecomputes block internals during backward instead of retaining every activation. Enabled by the training config; the model config default alone is False. No fixed 65% saving is demonstrated here.
BF16 / complex64Eligible CUDA operations use BF16, while recurrent complex tensors preserve real and imaginary FP32 components. Complex64 is eight bytes per value.
Tied vocabulary weightsShare one embedding/head matrix, saving 50,257×1024 = 51,463,168 parameter entries versus an untied head.
Unified projectionsOne input projection produces x/B/C/dt; one gate/up projection feeds SwiGLU. Fewer projections do not guarantee a measured speedup.
No causal convolutionThe block omits the convolution stage; SSD handles sequence mixing. Benchmarking is needed to quantify its performance effect.
Compile and TF32torch.compile uses max-autotune by default; TF32 is enabled on CUDA. Complex operations and backend support constrain attainable acceleration.
AccumulationCombines two micro-batches before an update. It reduces the batch needed at once, without reducing total token work.
MmapUseful for compatible serialized tensor shards. The raw-binary preparation bridge is currently missing.
Triton opt-inThe trainer requires ssd_dispatch='triton' and ENABLE_TRITON_KERNELS=1. At runtime the block catches kernel exceptions, warns once and uses PyTorch. This differs from the documented fail-loud policy.
Chunked CENot implemented in train_step. The full vocabulary logits are created before ordinary cross-entropy. It must not be counted as a current memory optimization.
Full-logit payload at B=16, T=2048, V=50257: BF16: 16 × 2048 × 50257 × 2 = 3.294 GB FP32: 16 × 2048 × 50257 × 4 = 6.587 GB These are tensor sizes, not total training peak memory.

Clipping and finite-loss recovery support stability, not throughput. The full pretraining run and quality comparisons remain unverified. No percentage memory saving, speed multiplier, perplexity parity or fixed A100 training time is asserted by this guide.
